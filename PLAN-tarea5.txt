# Tarea 5 — Cierre de viajes internos sin "Salir" + detección de salida por GPS

## Contexto
Hoy un viaje interno solo se cierra cuando el chofer toca "Salir" en la última parada
(`salirDeParada` → `cerrarViaje(..., { paradaQueSale })`). Si no lo toca, el viaje queda en
DESCARGANDO para siempre: no vence, el emisor de ETA sigue vivo (y le pega a la DB en cada tick,
porque `calcularEtaConApi` no cachea el "no hay paradas pendientes") y el precio real sale de un
acumulado GPS que sigue creciendo. Es el pendiente del Paso 3. Esta tarea agrega: (A) detección
de salida por GPS en cualquier parada, (B) un cierre manual por la PyME, (C) un cierre automático
a fin del día, (D) reglas de datos para los cierres sin "Salir", con el corte de precio separado
de la fórmula, y (E) el 409 sobre viajes cerrados, el bloqueo de dos viajes en curso y el arreglo
del ETA. El flujo normal (el chofer toca Salir a tiempo) no cambia.

## 1. Schema: solo aditivo (el `db push` lo corrés vos)

```prisma
enum CierreViaje  { CHOFER ORGANIZACION AUTOMATICO }   // nuevo, no toca enums existentes
enum OrigenSalida { CHOFER GPS }                        // nuevo

model Viaje {  // + 2 nullable
  cerrado_por        CierreViaje?   // quién cerró un FINALIZADO interno (null en legacy / viejos)
  fecha_corte_precio DateTime?      // instante en que terminó la medición del precio real
}
model Parada { // + 3 nullable
  salida_detectada DateTime?        // hora del PRIMER ping afuera (una vez por parada)
  origen_salida    OrigenSalida?    // de dónde salió salida_real
  no_visitada      Boolean?         // true = cierre automático sin llegar a esta parada
}
```

SQL esperado. Antes de mostrártelo final lo verifico con `npx prisma migrate diff
--from-schema-datasource prisma/schema.prisma --to-schema-datamodel prisma/schema.prisma --script`:
```sql
CREATE TYPE "CierreViaje" AS ENUM ('CHOFER', 'ORGANIZACION', 'AUTOMATICO');
CREATE TYPE "OrigenSalida" AS ENUM ('CHOFER', 'GPS');
ALTER TABLE "viajes"  ADD COLUMN "cerrado_por" "CierreViaje",
                      ADD COLUMN "fecha_corte_precio" TIMESTAMP(3);
ALTER TABLE "paradas" ADD COLUMN "salida_detectada" TIMESTAMP(3),
                      ADD COLUMN "origen_salida" "OrigenSalida",
                      ADD COLUMN "no_visitada" BOOLEAN;
```
Decisiones:
- "No visitada" es una columna nueva y NO un valor nuevo en `EstadoParada`. Así no hay
  `ALTER TYPE ... ADD VALUE`, que rompe al Prisma de un deploy viejo que lea la fila (ver la regla
  de enums en CLAUDE.md). La parada queda `estado PENDIENTE` + `no_visitada true`.
- Los dos enums nuevos solo viven en columnas nuevas. El Prisma viejo no las selecciona, así que
  no tira.
- "FINALIZADO incompleto" se deriva en el read (`paradas.some(no_visitada)`); no lleva columna
  propia.
- "Peón no medido" también se deriva: la parada tiene `llegada_real`, `salida_real` en null y
  `peon_real_horas` en null en un viaje terminado. No lleva columna.
- Sin índices ni FKs nuevos.

## 2. Funciones puras (unit tests sin red)

**`src/services/cierre-fechas.js`** (reusa `partesLocales` / `localAUtc` de `serie-fechas.js`; a
`localAUtc` se le suma un `segundo` opcional, default 0, compatible con lo que ya hay):
- `horaPrevistaFin(ultimaParada)` = `llegada_real + peon_estimado_horas`. Es null si todavía no
  llegó. Si la parada no tiene peón estimado (viaje viejo), usa `tiempoPeonMinutos()`.
- `finDelDia(fecha_inicio)` = 23:59:59 America/Argentina/Buenos_Aires del día LOCAL de inicio.
  Con la variable [SOLO TESTS] `CIERRE_FIN_DIA_SEGUNDOS_TEST`: `fecha_inicio + N s`.
- `momentoCierreAutomatico(viaje)`: si llegó a la última y `prevista > finDelDia`, devuelve
  `prevista + CIERRE_EXTENSION_MINUTOS` (120). Si no, `finDelDia(fecha_inicio)`.
- `cierreManualDisponibleDesde(viaje)`: si llegó a la última,
  `min(prevista, salida_detectada de la última)`. Si no, null.

**`src/services/salida-deteccion.js`**:
- `evaluarPingSalida(estado, ping, parada, { metros, segundos, ahora })` →
  `{ estado: nuevo|null, detectada: Date|null }`.
  - No corre si la parada no tiene `llegada_real`, si ya tiene `salida_real` o
    `salida_detectada`, o si `ping.ts <= llegada_real`.
  - El timestamp del ping se descarta si está más de 60 s en el futuro respecto del server: es
    hora del celular, y así no se puede adelantar la detección.
  - Pings desordenados (`ts <= estado.ultimo_ts`): se ignoran.
  - Un ping afuera (> metros, con `distanciaMetros` de parada.service, que es turf/haversine
    local) arranca `fuera_desde = ts` si no estaba armado.
  - Un ping adentro → `estado null` (reset).
  - Un ping afuera con `ts - fuera_desde >= segundos*1000` → `detectada = fuera_desde`.
  - Si el estado guardado es de otra parada (`id_parada` distinto), se arranca de cero.

**`src/services/cierre-plan.js`** (dice el instante de corte; no sabe de precios):
- `elegirSalidaReal({ salida_detectada, toque })`: si hay detectada y es anterior al toque,
  `{ salida_real: salida_detectada, origen_salida: 'GPS' }`. Si no,
  `{ salida_real: toque, origen_salida: 'CHOFER' }`.
- `planCierre(viaje, modo, ahora)` → `{ estadosEsperados, abierta, salida
  ({fecha, origen}|null), noVisitadas[], corte, incompleto }`.
  - `instanteCorte` está adentro y es lo único que decide CUÁNDO termina la medición. La tabla
    está en la sección 6.

**`src/services/mediciones-gps.js`** (puro): `medicionEn(puntos, acumulado, T)` →
`{ tiempo_horas, distancia_km }` hasta T. Detalle en la sección 6.

**`src/services/precio-real.js`** (puro, la FÓRMULA, la única): `precioDesdeMediciones({ zona,
paradas, tarifa_hora, tarifa_km }, { tiempo_horas, distancia_km })` →
`{ precio_real, precio_por_tiempo, precio_por_distancia, tiempo_capital, distancia_provincia }`.
Es el bloque que hoy está duplicado en `cerrarViaje` (líneas 64-75) y en
`calcularCostoAcumulado`; los dos pasan a usarlo y el resultado es idéntico. El día que cambie la
fórmula, se cambia solo acá.

`tiempos-reales.js`: no cambia el cálculo. Una parada abierta sin salida y sin `fin` ya da peón
null y no suma a `peon_horas`. Se agrega `paradas_peon_no_medido` al resultado, y `bloqueTiempos`
expone en `real` el campo `peon_completo: false` cuando hay alguna. `duracion_real` y
`duracion_descarga` salen null solas, porque la última no tiene `salida_real`. Con eso queda
excluido de métricas y promedios.

## 3. Detección en `gps.socket.js` (A)

Dónde se engancha: después de `actualizarAcumulado` y del primer `relimpiarSiCerrado`, y antes
de `iniciarEmisorEta`. Solo corre si el viaje es interno y está en CARGANDO o DESCARGANDO. Usa
las `paradas` que ya trae el `findUnique` del ping: hoy trae todas las columnas, y desde ahora
también `salida_detectada`. **Cero queries nuevas por ping.**

```
const abierta = paradas.find(p => p.llegada_real && !p.salida_real)
if (interno && ESTADOS_EN_PARADA_INTERNO.includes(estado) && abierta && !abierta.salida_detectada)
  await procesarPingSalida(io, viaje, abierta, { lat, lng, timestamp })
```
Además, para viajes internos, en cada ping va `registrarPuntoMedicion(id_viaje, timestamp,
acumulado)` (solo Redis, ver sección 6).

**`src/services/salida-deteccion.service.js`** → `procesarPingSalida`:
1. Lee `gps:{id}:salida` (JSON `{ id_parada, fuera_desde, ultimo_ts }`) y llama a
   `evaluarPingSalida`.
2. Guarda el estado nuevo con `EX` = `segundos + 600`, o hace DEL si quedó en null.
3. Si detectó: `parada.updateMany({ where: { id_parada, salida_real: null, salida_detectada:
   null }, data: { salida_detectada } })`. Es la ÚNICA escritura a la DB, una vez por parada.
   Con `count === 1`:
   - emite `parada:salida_detectada` al chofer y a la PyME;
   - si es la última parada y el cierre manual todavía no estaba habilitado por tiempo,
     emite `viaje:cierre_habilitado` con motivo GPS;
   - hace DEL de la key.
4. Nunca tira: loguea `[salida-deteccion] ...`. Un fallo no puede romper el ping.

`limpiarGPS` suma las keys `gps:{id}:salida` y `gps:{id}:puntos`.

**Salir con salida detectada (A6)**: en `salirDeParada` (intermedia y última), `ahora` pasa a ser
el "toque" y `elegirSalidaReal` decide `salida_real` y `origen_salida`. El guard sigue igual
(`salida_real: null` en el WHERE). El manejo del tramo siguiente ya sale de
`anterior.salida_real` en `confirmarParadaInterna`, así que toma la hora detectada sin tocar
nada. Si no hubo detección, el flujo es el de hoy y solo se suma `origen_salida: 'CHOFER'`.

## 4. Cierre unificado: `cierre.service.js`

`cerrarViaje` LEGACY no cambia, salvo que usa `precioDesdeMediciones`. El camino interno pasa a
`cerrarViajeInterno({ io, id_viaje, modo: 'CHOFER'|'ORGANIZACION'|'AUTOMATICO', actor, ahora })`,
y lo usan los tres modos:
1. Lee el viaje con sus paradas y arma `planCierre(viaje, modo, ahora)`.
2. Calcula `mediciones = medicionesHasta(id_viaje, plan.corte)` (Redis) y el precio con
   `precioDesdeMediciones(...)`. Todo fuera de la tx.
3. Abre UNA tx (OPCIONES_TX):
   - `viaje.updateMany({ where: { id_viaje, estado: { in: plan.estadosEsperados } }, data:
     { FINALIZADO, cerrado_por, precio_real, tiempo_capital, distancia_provincia,
     distancia_real_km: mediciones.distancia_km, fecha_corte_precio } })`. `count === 0` →
     CierrePerdido.
   - Si hay salida, la parada abierta: `updateMany({ salida_real: null })` → salida y
     `origen_salida`. `count === 0` → CierrePerdido.
   - Las paradas no visitadas: `updateMany({ llegada_real: null })` → `no_visitada: true`.
   - `escribirRealesInterno(tx, ...)` sin `fin`: la parada abierta sin salida queda con peón null.
4. Fuera de la tx, lo de siempre:
   - historial FINALIZADO (origen CONDUCTOR / CLIENTE / SISTEMA);
   - remito y relectura;
   - `viaje:finalizado`, que ahora también llega a la sala del chofer y suma `cerrado_por`,
     `incompleto` y `paradas_no_visitadas`;
   - `marcarViajeCerrado`, `detenerEmisorEta`, `cancelarAvisoVencimiento`,
     `cancelarTimersCierre` y `limpiarGPS` (que ahora incluye las keys de detección y de puntos).

Si dos cierres compiten (Salir del chofer, finalizar de la PyME, el automático), todos usan
`updateMany` con el estado en el WHERE: gana uno y el resto ve `count 0` → 409. Para que el que
pierde reciba el mensaje del punto E16 y no un 409 genérico, se relee `cerrado_por`.

`limpiarViajeActivo` (cancelaciones de chofer, PyME y admin, y desvinculación) suma
`cancelarTimersCierre`. El Map vive en un módulo chico (`timers-cierre.js`) para no armar un
import circular con cierre.service.

Transiciones nuevas en `TRANSICIONES_INTERNO` (la tabla de estado-viaje.service.test.js se
actualiza):
- DESCARGANDO → FINALIZADO: además del chofer, ahora PYME y SISTEMA.
- CARGANDO → FINALIZADO y EN_RUTA → FINALIZADO: solo SISTEMA (el automático incompleto).

## 5. Endpoint nuevo y campos del read (B)

**`POST /api/organizaciones/:id/viajes/:idViaje/finalizar`**: sin body, cualquier miembro activo
(RESPONSABLE o MIEMBRO, por `requireMiembro`). Se permite con la PyME SUSPENDIDA, igual que
cancelar. Orden:
1. Chequeos perezosos (vencimiento y cierre).
2. Viaje de otra PyME o inexistente → 404.
3. Ya FINALIZADO → 409 "El viaje ya fue cerrado (por el chofer / la empresa / automáticamente)".
4. Otro estado que no sea en curso → 400 `mensajeEstado('finalizar', estado)`.
5. Todavía no llegó a la última parada → 409 "El chofer todavía no llegó a la última parada".
6. No está habilitado → 409 "El cierre manual se habilita a las HH:MM (hora prevista de fin) o
   cuando el GPS detecte la salida de la última parada".
7. Carrera perdida → 409.

Respuesta: `{ mensaje, id_viaje, estado: 'FINALIZADO', cerrado_por: 'ORGANIZACION', precio_real,
remito_url, salida_real, origen_salida, peon_medido, estimado, real }`.

Cableado: `finalizarViajeOrganizacion` en viaje-interno.service, `finalizarViajePyme` en
viajes-internos.controller, y la ruta en organizaciones.routes.

**Read** (`serializarViaje`: PyME y chofer, en listas y detalle):
- bloque `cierre`: `{ cerrado_por, incompleto, cierre_manual_desde, cierre_manual_habilitado,
  motivo_habilitacion: 'TIEMPO'|'GPS'|null, hora_prevista_fin, cierre_automatico_en,
  fecha_corte_precio }`;
- en cada parada: `salida_detectada`, `origen_salida`, `no_visitada` y `peon_medido`.

El chofer ve los mismos campos (le sirven para el "tocá Salir"). `paradaVistaChofer` sigue
sacando solo el lugar.

## 6. Timer, barrido y chequeo perezoso (C), sin pollers

**`src/services/cierre-automatico.service.js`**, mismo idiom que `vencimiento.service`:
- `programarCierreAutomatico(io, id_viaje, momento)`. Se arma en `iniciarViajeInterno`, con
  `finDelDia`. Se REprograma en `confirmarParadaInterna` cuando confirma la ÚLTIMA parada: ahí
  cambia `momentoCierreAutomatico` si la prevista pasa el fin del día. Al disparar RELEE la
  fila; si todavía no toca (overflow de setTimeout, reloj corrido), se re-arma.
- `programarAvisoCierreHabilitado(io, id_viaje, prevista)`: se arma al confirmar la última. Al
  disparar relee, y si el viaje sigue en curso y no lo había habilitado ya el GPS, emite
  `viaje:cierre_habilitado` con motivo TIEMPO.
- `cerrarSiCorresponde(io, where)`, el chequeo perezoso. Lo scopea cada caller:
  `{ id_organizacion }`, `{ id_conductor }` o `{ id_viaje }`.
  - Hace UNA query de viajes internos en curso con un filtro grueso en SQL (`fecha_inicio` antes
    del día local siguiente a `ahora`) y decide exacto en JS con `momentoCierreAutomatico`.
  - Se llama junto a `vencerSiCorresponde`, con un helper `ponerAlDia(io, where)` que corre los
    dos.
  - Lo usan: las listas y el detalle de la PyME y del chofer, `salir`, `confirmar-parada`
    interno, `iniciar` (scope `{ id_conductor }`, para que un viaje de ayer colgado no bloquee el
    de hoy), `finalizar` y `cancelar` de la PyME.
  - El admin NO lo usa (mismo criterio que D10).
- `barridoInicialCierres(io)` en app.js, UNA query (los internos en curso con sus paradas):
  - los vencidos se cierran AUTOMATICO, en secuencia;
  - al resto se le arma el timer de cierre y, si ya llegó a la última y la prevista no pasó, el
    aviso de habilitación;
  - log `[cierre-automatico] barrido de arranque: N en curso, X cerrados, Y programados`;
  - kill-switch `CIERRE_BARRIDO_ARRANQUE=0` [SOLO TESTS], porque escribe en la DB compartida;
  - `CIERRE_BARRIDO_ID_ORGANIZACION` [SOLO TESTS] lo limita a una PyME, para que el test del
    barrido no cierre viajes reales.

**Instante de corte (`instanteCorte`, en cierre-plan.js) y precio en cada caso**:

| Cierre | Salida de la parada abierta | Corte del precio |
|---|---|---|
| CHOFER, Salir sin detección (flujo normal) | toque, origen CHOFER | toque → mediciones = acumulado completo (**idéntico a hoy**) |
| CHOFER, Salir con detección anterior | detectada, origen GPS | detectada |
| PyME o AUTO, llegó a la última, con detección | detectada, origen GPS | detectada |
| PyME o AUTO, llegó a la última, sin detección | vacía, peón no medido | llegada a la última + peón estimado (= hora prevista de fin) |
| AUTO sin llegar, parado en una parada | detectada si hay; si no, vacía | detectada; si no, llegada a ESA parada + su peón estimado |
| AUTO sin llegar, EN_RUTA | — | `min(último ping, salida_real de la anterior + manejo estimado del tramo siguiente)` |

Justificación del último caso, que pediste que propusiera. El manejo después de salir existió (el
GPS lo prueba), pero sin llegada no se sabe cuándo terminó. "Último instante medido = salida
anterior" le cobraría de menos al chofer un tramo que hizo. "Último ping" le cobraría el viaje a
su casa. El manejo estimado del tramo es la cota razonable, y el último ping la recorta si el GPS
se cortó antes. En las paradas que no visitó no se inventa nada: quedan `no_visitada` y sin
tiempos.

**Mediciones hasta T** (para que el precio NO siga creciendo con el GPS): `registrarPuntoMedicion`
hace ZADD a `gps:{id}:puntos` (score = ts del ping, valor = `{ts, tiempo_horas, distancia_km}` del
acumulado), con muestreo de 30 s como mínimo: unos 2900 puntos en 24 h, con TTL de 24 h como el
acumulado. `medicionesHasta(id, T)`:
- si T es igual o posterior al último ping, devuelve el acumulado tal cual (flujo normal sin
  cambios);
- si no, toma el último punto ≤ T: el tiempo es exacto (`punto.t + (T - punto.ts)`) y la distancia
  es la del punto, con un error de 30 s de manejo como máximo.

`medicionEn` es la parte pura. Si no hubo pings, las mediciones son 0 y la distancia real queda
null, como hoy.

Precio en vivo (`costo:actualizar` / `costo-acumulado`): sigue creciendo mientras el viaje esté
abierto. El corte aplica al precio REAL del cierre. Si querés, en otra tarea se puede congelar el
vivo pasada la prevista.

## 7. Otros (E)

- **E16**: `salirDeParada` y `confirmar-parada` interno, sobre un FINALIZADO con `cerrado_por`
  ORGANIZACION o AUTOMATICO → 409 "El viaje ya fue cerrado por la empresa" / "...
  automáticamente". En confirmar-parada el chequeo va justo después del 403 (orden nuevo para
  internos: 404 → 403 → cerrado 409 → parada ajena → ...; queda documentado en API.md). Los pings
  de un viaje cerrado ya se ignoran en silencio (`ESTADOS_TERMINALES`) y no se toca.
- **E17**: en `iniciarViajeInterno`, después de los 400 de estado y antes de la ventana y la
  proximidad, si el chofer tiene otro viaje en `ESTADOS_EN_CURSO` (cualquier ciclo) → 409 "Ya
  tenés un viaje en curso (#N): terminalo antes de iniciar otro". Se re-chequea en la tx con
  `SELECT ... FROM conductores WHERE id_conductor = $1 FOR UPDATE` antes del `updateMany`. Orden
  de locks: chofer → viaje; nadie más bloquea al conductor, así que no hay deadlock. Se saca de
  "PENDIENTE" en CLAUDE.md.
- **E18**: `eta-emisor.js` suma un Map `sinPendientes`. Cuando `calcularEtaConApi` (o
  `recalcularEtaInmediato`) devuelve null, se marca, y los ticks siguientes salen sin tocar la DB
  ni Redis. Se borra en `detenerEmisorEta`. En los dos ciclos, una parada confirmada no vuelve a
  quedar pendiente, así que la marca es definitiva para ese emisor.
- **E19**: el flujo normal cambia solo en que escribe `origen_salida: 'CHOFER'` y
  `cerrado_por: 'CHOFER'`. El precio sale del mismo acumulado.
